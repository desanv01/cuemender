## R01 — Correct the actual OBS protocol boundary (high)

Locations: internal/obs/obs.go InputAudioTracks; manager.go completeTracks; protocol fixtures/compatibility note.

- Wire inputAudioTracks uses string keys "1"–"6". goobs returns them unchanged. Convert at the adapter boundary to the existing domain track1–track6 convention; validate all six bool entries. Missing/malformed fields remain unknown; do not fill absent values with false.
- Keep the domain convention stable for later repair logic; document both directions so P04 will map domain keys back to numeric wire keys.
- Add real local WebSocket protocol tests using the pinned GoobsDialer/backend, not only fakeBackend. Capture actual outbound request types/target identifiers, assert the read-only allowlist, and test success, missing fields and protocol errors.
- Pass TestReviewOBSRealWireTrackMap. Correct the compatibility note which currently describes the synthetic fake map as wire normalization.

## R02 — OBS connection loss, cancellation and saved credentials (high)

Locations: internal/obs/{obs,manager}.go and app shutdown/startup wiring.

- Distinguish a per-field unsupported read from transport failure. If the transport is lost, immediately invalidate usable observations/discovery/readiness, change connection status, increment generation and redial with bounded backoff until success or explicit disconnect. Never keep refreshing observed_at into a false fresh/connected state.
- Close/abort the active transport before waiting for blocked workers. Honor cancellation during dial/authentication/read and bound total disconnect/shutdown duration; a context argument checked only before an SDK call is insufficient. Ensure abandoned attempts and failed authentication free sockets.
- Do not allow sequential reads for many scenes to extend shutdown indefinitely. Track/stop/join worker goroutines; no transport may be installed after disconnect/Close.
- Endpoint-scoped credentials must load in a fresh manager when the saved configured endpoint is explicitly connected. Use the exact validated endpoint key; do not rely on a previous in-memory endpoint. A changed endpoint never inherits another endpoint's password. Keep omission vs explicit empty semantics.
- Resume saved OBS setup at startup only when usable saved setup exists (C08); do not dial merely because a default address exists. If credential/setup state cannot identify an intentionally configured unauthenticated endpoint without an additive config field, report that design choice to Codex instead of inventing a new flag silently.
- Pass the saved-password and closed-socket review tests. Add established-loss -> reconnect/new generation -> successful observation, manual-disconnect stopping retry, and actual SDK stalled-response/cancel tests. Retain passing P01 lifecycle guarantees.
- Configure a controlled SDK logger so malformed/provider payloads do not bypass app redaction through goobs stderr logs; test a synthetic sentinel. No raw payload logging.

## R03 — Fresh identity, configuration provenance and coherent snapshots (high)

Locations: OBS discovery/polling/resolution, domain integration types and app private projection.

- Discovery must update after source/scene changes and collection changes. Use narrow read-only OBS event subscriptions plus rediscovery, or a bounded polling/context strategy with a documented freshness bound. GET discovery must not pretend a forever-cached snapshot was refreshed.
- Bind discovery/readiness to actual scene collection/context, input UUID/name and direct scene+item+source identity. A name-only/ambiguous match after context loss must require reselection. Reject changed/deleted/recreated identities; preserve partial/offline structural settings saves without claiming ready.
- Capture settings revision and connection/context generation before reads; return those provenance fields and discard stale results if either changes. Pass the persisted Settings revision to the manager rather than only Expectations.
- Invalidate cached observations when settings change. Reject older asynchronous results after the new revision. A UI timestamp alone is not enough.
- Snapshot connection, discovery, observation and resolution coherently (one snapshot boundary or generation/revision-checked composition); App currently obtains them independently and can mix generations.
- Pass TestReviewOBSRejectsRecreatedInputDuringConnection. Add tests for scene collection replacement/reused item IDs, deleted/renamed source, no-UUID ambiguity, slow old-config read finishing after a settings save, and reconnect with old results.
- Tests must exercise the manager/app boundary, not merely call inputResolves with a handcrafted already-updated list.

## R04 — Twitch validation, revocation and explicit storage policy (high)

Locations: twitch manager OAuth startup/maintenance/refresh, app credential availability.

- Call /validate at startup and on the hourly schedule. Check client, user subject, required scopes and positive expiry; compare saved/refreshed subject to the existing own-channel identity. A different identity requires a new explicit authorization.
- Validate rotated access tokens before use. Do not restore missing scopes from old credentials. Schedule refresh before expiry as appropriate; do not rely solely on an hourly blind refresh for short-lived tokens.
- Distinguish expired credentials eligible for refresh from revoked/invalid binding/scope credentials requiring authorization. On terminal authorization failure stop intake, replies and reconnect work; do not just change the status string.
- EventSub authorization revocation and Helix authentication rejection must enter this same lifecycle decision, not an endless ordinary reconnect loop. Distinguish transient network failure from terminal authorization failure.
- Refuse a new credential-dependent flow when OS storage is already unavailable unless --session-only-secrets was explicitly selected. Do not silently establish a memory-only initial session on an unavailable keyring.
- If persisting a legitimately rotated pair fails after a previously established session, use the validated rotated pair consistently for the current run, report persistence degraded, and prevent restart from being misrepresented as durable. This is distinct from silently choosing memory-only setup.
- Pass TestReviewHourlyLoopActuallyValidates; add maintenance validation failure, identity/scope/expiry mismatch, terminal revocation stopping calls, and rotation-save-failure tests.

## R05 — Serialize lifecycle transitions and credential/config writes (high)

Locations: twitch Connect/Disconnect/Close/saveCredentials/refresh, app integration methods.

- Make successful disconnect a real boundary: no already-started credential Save may complete after its final Delete. Serialize save/delete with lifecycle ownership and recheck generation at the protected write; merely checking before an unprotected store call is not enough.
- Track/join the refresh loop and its active operation; use connection cancellation, not only manager-wide context. Synchronize worker registration with disconnect/close; avoid WaitGroup Add/Wait and Connect/Disconnect interleavings.
- Guard every async state/receipt install under the same lock that checks generation. A current(gen) call before acquiring the mutation lock leaves a race. Clear pending instructions, credentials and replies at the transition.
- Serialize each provider's app-level busy check, config persistence and connect/disconnect transition. Concurrent connect requests must not save the losing request's client ID/endpoint while the winning worker uses another value. Preserve independent config updates and CLI-listen isolation.
- Test failure ordering across JSON config and keyring; do not imply an atomic transaction spanning both. Add deterministic write/sync/replace failure injection (or a controlled real filesystem failure) and verify old valid config bytes/cache survive with no connected-success publication.
- Pass TestReviewRefreshCannotRestoreDeletedCredential. Add barrier-based concurrent Connect/Disconnect/Close, late device result, refresh/delete and two competing client/endpoint requests. Assertions must cover final persisted state and actual worker lifecycle, not just final UI text.

## R06 — EventSub socket ownership and generations (high)

Locations: twitch runSocket/startEventSub and lifecycle-owned reply setup.

- Own and close whichever socket is active after any number of requested handovers. Always retire old sockets after successful welcome, close failed replacement attempts, and close the final replacement on cancellation/error.
- Increment/invalidate transport generation for ordinary reconnect/replacement and carry it on normalized events. Suppress old deliveries and stale queued replies. Separate logical authorization ownership from socket generation if needed.
- During requested handover, preserve event intake on the old connection until the replacement is ready; do not discard the old socket's interval of notifications merely while synchronously dialing/reading the replacement.
- Mark connected only after a welcomed/subscribed usable session; an acquired token alone is not "chat connected." Reset retry backoff after successful recovery.
- Validate reconnect URL scheme/host/authority, including unexpected userinfo/port; keep bounded protocol reads/deadlines.
- Pass TestReviewHandoverClosesReplacementSocket and add multi-handover, cancellation while replacement welcome is pending, ordinary reconnect generation and no unnecessary handover resubscription tests. Use a local real coder/websocket lifecycle fixture in addition to fakeSocket.

## R07 — Rate limits and normalized chat seam (medium)

Locations: twitch commands/oauth/handleChat.

- Propagate sanitized provider throttling metadata from Helix (Retry-After and applicable reset/remaining headers). Defer subsequent queue items until the stricter deadline. Do not blindly resend a timed-out/ambiguous message; throttling the queue is different from replaying the failed send.
- Drain expired queued items without leaving later items stranded, reject enqueue after close, and make shutdown wait for sender exit within the lifecycle bound. Queues belong to the active authorization lifecycle.
- Bound/expire actor cooldown state as well as dedup state. Retain 10-second issue cooldown and documented 24-hour/10,000-ID dedup policy.
- Add the C04 typed normalized event/callback seam containing delivery/message IDs, broadcaster/actor IDs, received_at, command/category or incident code, and generation. P02 may use it only for private receipt diagnostics; do not implement incidents.
- Test 429 with a later queued reply, send failure without replay, expiry draining, post-close behavior, cooldown eviction and normalized !fixed/!stillbroken IDs. Keep raw chat and identities off the public projection.

## R08 — Complete minimal private setup and preserve selected identities (medium)

Locations: web/control/app.js/index.html and actual-control-script fixtures.

- Retain discovered visual source UUID and scene/context binding in settings round-trip; current collectSettings drops the UUID. Preserve correct IDs across select -> save -> reload -> save. Clear/revalidate IDs if the operator edits names manually.
- Clear old discovery controls/state on disconnect or invalidated generation. Keep current selections when a refresh changes only timestamps and identities are still valid; do not reset the form on every poll.
- Render private setup resolution and the actual typed OBS observation: mute, all six track flags, current scene, selected visibility, broadcasting, observed time and unknown/stale state. This enables P02's promised real comparison. No source data on public overlay.
- Keep track confirmation explicit and avoid implying local settings prove audience playback. No final design work required.
- Exercise actual JS handlers for selection/save/reload/disconnect and private errors, not only initial rendering. Perform a real browser smoke if available, otherwise record that gate as unmet. Preserve P01 reload-CSRF tests.
- Fix setup documentation to match the tested UI; do not claim OBS provides a localhost binding control unless verified. CueMender's loopback client restriction is distinct from the OBS server's network listen configuration.
