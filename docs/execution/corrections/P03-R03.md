## A — Honest durable recovery and interruption

- Propagate startup recovery/read failures to App.New and release partially initialized resources. A constructor returning an error or an explicit initialization method is an internal implementation choice; update all callers. Do not continue with empty history after a store failure.
- Make recovery/session interruption updates atomic, or document and implement an idempotent retry boundary that cannot report successful partial recovery. Test injected update failure with the real store, successful retry, monitoring off, and prior open records interrupted.
- Remove the blanket 500-record cache truncation of retained open/unresolved records. Keep the existing 500/30-day completed-history policy; ensure retained non-completed records remain addressable/recheckable/dismissible. Use a scoped query/loading fix, not a UI redesign. Test >500 records with a retained record outside the initial page and query errors.
- Manual Stop must return persistence failure, avoid publishing an unsaved outcome and remain recoverable/retryable after the fault clears. Do the same for affected stop/invalidate/reload/result paths. Preserve canceled job ownership until actual completion; do not restore concurrent read admission just to make stop pass.
- Required tests: TestReviewR02StartupRecoveryErrorPropagates, TestReviewR02ManualStopFailureIsReported, recoverable SQL fault/retry with cache/storage agreement and >500 retained-record access.

## B — Cancellable admission and originating-session ownership

- Replace unbounded opMu admission with context-aware serialization, or equivalent bounded ownership. Cancellation must prevent persistence even when another operation owns the gate. Do not hold a gate while waiting for a worker that needs it. Result/store work needs an owned, bounded context; do not evade shutdown cancellation with Background.
- Require connected/current nonzero Twitch generation before processing queued reports and feedback. Capture the monitoring session identity at intake and revalidate it through durable mutation and reply enqueue. Receipt timestamps alone are not sufficient. Sessionless help remains eligible while Twitch is connected and current; idle help must not create an incident/session.
- Preserve single bounded ReplyQueue and exact commands, cooldowns and dedup. Drop canceled/stale queue work and join intake on close. Do not treat current generation zero as permission to process old events.
- Required tests: TestReviewR02CanceledGateReturnsPromptly, TestReviewR02DisconnectedTwitchRejectsQueuedReport; stale feedback; queued report across stop/start; session change before reply enqueue; connected-idle !streamhelp; canceled gate/blocked store admission followed by whole-app close.
- If synchronization primitives change, adapt only the review test's mechanism for holding the gate. Preserve its assertion: a canceled operation returns without waiting for the other owner and makes no mutation. Record the exact test adaptation; do not remove failure coverage.
