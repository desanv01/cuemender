## 1. OBS transport ownership from handshake through shutdown (R02 B)

Primary files: internal/obs/obs.go, manager.go, focused protocol tests; app lifecycle tests where needed.

- Make dial, OBS Hello/Identify and SDK requests cancellable with actual transport ownership. goobs.New currently returns the client only after authentication, so publishing a candidate after New does not cover handshake cancellation. Investigate the pinned SDK and its supported dialer hooks; own the underlying connection from acquisition and close it on cancellation or constructor failure. Prefer a narrow adapter change. If it truly requires a dependency change, stop that dependent portion with the smallest concrete proposal for Codex; do not silently substitute it.
- Bound and join work. callRead currently returns on cancellation but leaves result and Close goroutines unjoined. Track SDK calls and cleanup, stop admitting reads during close, and prevent unlimited explicit discovery calls from accumulating SDK work. Do not merely replace one blocked call with an unbounded goroutine.
- Serialize manager Connect/Disconnect/Close and worker registration. Cancel/close resources before waiting; callbacks must not create lock/join deadlocks. Track explicit RefreshDiscovery work as well as periodic workers.
- Pass TestReviewR03OBSHelloCancellation and preserve initial-Version/read cancellation tests. Cover withheld Hello/Identify, failed auth, later stalled request and reconnect cancellation against the actual local WebSocket adapter. Prove peer socket closure and joined work. A timeout return alone is insufficient.
- Add the already-required production-app shutdown case with a blocked OBS provider and active HTTP/SSE client: application exits within its configured bound, listener releases, database reopens, owned workers/sockets stop. No real OBS needed.

## 2. Capture OBS evidence context before reading (R02 C)

Primary file: internal/obs/manager.go and focused manager tests.

- Capture settings revision, connection generation and identity context before the operation. Pass those captured values through initial connect, reconnect, poll and GET refresh; install only if they still match. Do not assign current revision at the end to make an old result appear current.
- Read collection before Inputs/Scenes, then after the complete identity sequence. Both successful, nonempty, equal reads are required for known context. An initially failed read cannot be repaired by one final success. Discard ambiguous observations; name-only references must not retarget automatically after context loss.
- Define one coherent readiness predicate: usable connected transport, fresh observation, matching requested/current revision, matching discovery/observation generation and context, resolved mic/source/scene identities. Stale or context-unknown data is not ready. Retain private stale display where appropriate, while omitting observations from superseded settings revisions.
- Replace expectationsEqual's fmt pointer comparison with typed value equality or reflect.DeepEqual for this small value structure. Do not rename storage or broaden the domain.
- Pass TestReviewR03OBSStaleCannotBeReady, TestReviewR03OBSUnknownStartContextStaysUnknown and TestReviewR03OBSRefreshCannotRelabelRevision. Add/reuse barrier tests for settings changes during initial/reconnect/poll/GET, context switches at the beginning/middle/end, and same-name scene recreation with mismatched UUID. Preserve all passing identity tests.

## 3. Twitch authorization lifecycle and lossless handover (R02 A/D)

Primary files: internal/twitch/manager.go, commands.go, oauth.go and their tests.

- Apply a consistent lifecycle scheme to Connect/StartSaved/Disconnect/Close, including worker registration. Disconnect currently has no lifecycleMu despite the report. Cancel and join authorization-owned validation/refresh/reply operations; manager-lifetime context is not enough. Avoid self-join from sender/auth-failure callbacks.
- Take immutable credential snapshots for unlocked provider work. Check generation under the lock that installs credentials, changes receipt counts/connection generation or admits normalized commands. Bind queued replies to their intended lifecycle; never send old queue items using a newly authorized account.
- During requested handover, keep exactly one reader on each owned socket and continue old notifications until replacement welcome is usable. Handle duplicate delivery through existing dedup; then retire old socket/read work. Cancellation and replacement failure close all owned sockets. Reset backoff after stable recovery. Preserve own-channel identity rules and URL validation.
- Complete transient-versus-terminal handling on startup as well as maintenance/refresh. A timeout/5xx during the second startup Validate must not be called revocation. Test changed startup subject, invalid rotated expiry, and short-token scheduled maintenance (60 seconds, ten minutes, one hour) with deterministic clock/timer seams rather than long sleeps. Keep validated rotated pairs after persistence failure and preserve the existing serialization of credential persistence/deletion.
- Preserve queue close/join/drain fixes and no blind replay of ambiguous sends. Honor applicable provider remaining/reset metadata as already required by R02; document the supported headers with local HTTP fixtures.
- Pass TestReviewR03HandoverProcessesOldNotifications and TestReviewR03DisconnectCancelsMaintenance. Add the remaining barriers: concurrent lifecycle registration, stale command/queue result after disconnect/new authorization, blocked refresh/validation cancellation, terminal Helix failures, delayed handover using real coder/websocket. Synthetic sockets are useful but not the only required adapter evidence.
