## R01 — Restore authenticated browser saves after reload

- Restore the CSRF token from the authenticated private state response before permitting saves.
- Keep the token private/in-memory; don't put it in public SSE, localStorage or logs.
- Verify bootstrap -> save -> reload without fragment -> save again, and opening /control/ with the existing valid cookie.
- Exercise actual JS. The review includes a small reproduction; a real browser run is preferred if available. A backend-only handler test cannot prove this fix.
- Preserve invalid-session/expired-bootstrap handling.

## R02 — Make settings/state/publication ordering coherent

- Serialize successful settings commits with installation of their cached state and ordered publication.
- Ensure a subscriber's initial snapshot cannot be followed by an older publication.
- Preserve compare-and-update revision conflict behavior and keep failed persistence from publishing success.
- A narrow save mutex plus an appropriate state/publication critical section is sufficient if its lock order is sound. Do not introduce a queue framework or hold an unbounded network operation under the state lock.
- Test the real App and production hub, not only the duplicated testBackend/testHub.
- Required cases: concurrent conflicting saves yield one winner; sequential revision commits interleaved with subscriptions do not regress cached settings or SSE revisions; published/private state agrees with persisted latest settings after completion.
- Prefer synchronization/barriers to sleeps where a deterministic interleaving can be arranged. Document the invariant enforced; a race detector alone does not prove logical ordering.

## R03 — Resolve shutdown failure and verify the intended scenario

- Reproduce/investigate the intermittent TestRunServesAndShutsDownWithActiveSSE failure.
- Keep the SSE client active when canceling the app; clean it up afterward even on test failure.
- Allow a justified test budget beyond the application's bounded shutdown budget, but don't merely increase timeout to conceal a stuck handler or leaked goroutine.
- If production shutdown/connection handling needs a narrow fix, implement it and explain the cause. Otherwise explain why the test was invalid and provide evidence.
- Verify port release and reopening the same database after shutdown.
- Run the focused lifecycle test repeatedly (at least five repetitions) and the full suite once after corrections.
- Attempt a normal-console compiled-binary Ctrl+C check with an isolated data directory. If the harness cannot deliver a real console event, report that precisely. Forced termination is not a passing signal test.

## R04 — Enforce credential-error redaction

- Public Error() text must use safe operation/category metadata, not append raw backend error text.
- If retaining an underlying cause for programmatic inspection, keep it outside normal formatted/logged output and don't inadvertently expose it through commonly used formatting.
- Test a backend error that deliberately includes a unique sentinel credential value. Verify safe error text/log representation excludes it while typed unavailable/not_found handling still works.
- Test relevant Get/Set/Delete error paths; no real credential required.
- Do not replace the keyring dependency or add a secret-scanning framework.
