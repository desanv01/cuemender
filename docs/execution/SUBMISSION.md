## How to capture actual Codex build footage

A real screen recording is the recommended format. There is no need to record every hour or make the whole video a coding tutorial. Capture genuine short moments during the work and later select a 20–30 second sequence.

### Capture while P04 is actually being built

1. Before the P04 request, open this Codex chat and the relevant project. Close unrelated windows and notifications. Keep Twitch tokens, OBS passwords and private bootstrap links off screen.
2. Start a screen recorder already available on the computer, such as OBS or an operating-system capture tool. Record the Codex application window at readable size; test a short sample first.
3. Capture the real request to implement the approval/repair engine and Codex's actual file edits/tool activity. Include enough visible context to identify the feature and the project.
4. Capture a readable source diff or relevant excerpt of the proposal checks, durable intent or reconciliation logic. Narration explains why it matters; don't expect judges to read a whole file.
5. Capture the actual test command and result in Codex. If a real bug is found and fixed, that is useful footage; don't manufacture a failure to create a story.
6. Later cut from that build footage to the same feature functioning in the real Twitch/OBS demonstration.

Preserve original recordings locally. Edited excerpts and clearly labeled speed-up are fine as presentation choices; don't reconstruct a chat, fabricate logs, or imply a later replay was the original build. Source screenshots can supplement the sequence, but actual footage of the build activity is the clearest match to the supplied requirement.

### Recording practicalities

- 1080p is a reasonable target if the recorder/machine supports it; enlarge the app text and crop to relevant regions.
- Narration can be recorded afterward. Use short captions to identify "Actual Codex build" and "Live Twitch demonstration."
- Don't show login/password entry, environment files, credential-store contents or secret URLs. If accidentally captured, remove/blur that section and avoid uploading the raw source.
- If using OBS to record the screen, keep the recording capture/audio source separate from the mic/stream-track fixture being changed. A repair trial must not silently remove your narration from the recording. A separate recorder is another option.
- Keep a few seconds of lead-in/out and check legibility/audio immediately. This is easier than reconstructing missing evidence at the deadline.
- Do not infer that a specific clip length guarantees compliance; organizers judge the actual entry.
